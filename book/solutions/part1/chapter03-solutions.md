# Chapter 3. C 프로그램 구성요소 — 정답과 상세해설

> 본 문서는 Chapter 3 승인 원고의 확인 문제에 대한 별도 정답·해설이다.

## 문제 1. 프로그램의 구성요소 설명하기

### 정답

예제 A의 구성요소는 다음과 같다.

| 구성요소 | 해당 부분 | 역할 |
|---|---|---|
| 전처리 지시문 | `#include <stdio.h>` | 입출력 함수 사용에 필요한 헤더 정보를 포함한다. |
| 정의하는 함수의 이름 | `main` | 이 프로그램에서 작성한 작업을 시작하는 함수다. |
| 함수 몸체 | `main` 다음의 `{ ... }`로 둘러싼 부분 | 출력문과 반환문이 들어 있다. |
| 함수 호출문 | `printf("Study log ready.\n");` | 안내 문구와 줄바꿈을 출력한다. |
| 반환문 | `return 0;` | `main`을 끝내고 성공 종료 상태를 실행 환경에 반환한다. |

- `int`: `main`이 실행 환경에 정수 형태의 상태값을 반환한다는 뜻이다.
- `void`: `int main(void)`라는 형태에서 `main`에 매개변수가 없다는 뜻이다.
- `return 0;`: 화면에 0을 표시하지 않는다. `main`을 끝내면서 성공을 뜻하는 종료 상태를 돌려준다.

### 상세해설

예제 A에서 직접 정의한 함수는 `main`이고, 그 몸체 안에서 호출하는 라이브러리 함수는 `printf`다. 함수 이름을 찾으라는 질문에 `printf`만 적으면 정의하는 함수와 호출하는 함수를 구별하지 못한 답이 된다. 함수 몸체는 `main` 다음의 여는 중괄호에서 시작하여 대응하는 닫는 중괄호에서 끝난다.

`#include`는 빌드 과정에서 처리된다. 실행 환경이 `main`을 호출하면 이 예제의 몸체에서는 `printf` 호출문, 반환문 순서로 작업을 수행한다. 따라서 화면에는 `Study log ready.`와 줄바꿈이 나타나고, 0은 출력되지 않는다. 반환값과 화면 출력은 전달되는 곳과 목적이 다르다.

`void`는 이 형태의 `main`에 매개변수가 없다는 뜻이지, 실행 중 키보드 입력을 받을 수 없다는 뜻이 아니다. 또한 성공 종료 상태를 반환했다는 사실만으로 출력 내용이 요구사항에 맞았다고 보장할 수는 없다. 실제 출력은 예상 결과와 따로 비교해야 한다.

## 문제 2. 의도가 드러나는 주석 쓰기

### 정답

한 줄 주석의 모범답안은 다음과 같다.

```c
// 입력과 계산에서 같은 단위를 유지하기 위해 분 단위를 사용한다.
```

설명 내용을 두 줄로 적은 블록 주석은 다음과 같이 쓸 수 있다.

```c
/*
입력과 계산에서 같은 단위를 유지하기 위해
시간 기록은 분 단위로 통일한다.
*/
```

블록 주석은 중첩할 수 없다. 이미 열린 주석 안에서 `/*`를 다시 써도 새 주석 층이 생기지 않으며, 처음 만나는 `*/`에서 주석이 끝난다.

### 상세해설

두 답안 모두 “분을 사용한다”는 사실에 더하여, 입력과 계산의 단위를 일치시키려는 이유를 설명한다. 같은 의도가 드러난다면 “입력값과 계산값의 단위가 다르지 않도록 분으로 통일한다”처럼 다른 자연스러운 표현도 올바른 답이다.

`//`는 그 줄 끝까지를 주석으로 만든다. 블록 주석은 줄 수와 관계없이 `/*`에서 시작하여 첫 `*/`에서 끝난다. 모범답안에서는 구분 기호를 별도 줄에 두고 설명을 두 줄로 적었다. 구분 기호를 설명과 같은 줄에 배치해도 주석의 의미는 같다.

블록 주석을 중첩하려고 하면 안쪽 주석의 끝이라고 생각했던 `*/`가 전체 주석을 끝내 버릴 수 있다. 그러면 남은 설명이나 닫는 기호가 주석 밖에 놓여, 소스가 잘못 해석되거나 빌드가 실패할 수 있다. 주석은 프로그램이 수행하는 작업이 아니라 사람이 읽는 설명이므로, 코드와 의도가 바뀌면 주석도 함께 확인한다.

## 문제 3. 지시문과 문장 구별하기

### 정답

| 코드 | 종류 | 처리되는 때 | 세미콜론 |
|---|---|---|---|
| `#include <stdio.h>` | 전처리 지시문 | 빌드 중 전처리 단계 | 이 형태에는 붙이지 않는다. |
| `printf("Ready.\n");` | 함수 호출문 | 프로그램 실행 중 | 이 문장을 끝내는 `;`가 필요하다. |
| `return 0;` | 반환문 | 프로그램 실행 중 | 이 문장을 끝내는 `;`가 필요하다. |

`stdio.h`는 `printf`, `scanf` 같은 표준 입출력 기능을 사용하는 데 필요한 선언과 정보를 제공하는 헤더다.

### 상세해설

세 줄은 모두 소스에 적혀 있지만 처리되는 단계가 다르다. `#include`는 실행할 작업을 요청하는 문장이 아니라, 컴파일에 필요한 헤더 내용을 포함하도록 전처리 단계에 지시하는 줄이다. 반면 `printf` 호출문과 반환문은 `main`이 실행될 때 수행된다.

세미콜론의 차이는 이런 문법 형태의 차이에서 나온다. `#include <stdio.h>`에는 `;`를 붙이지 않고, 제시된 함수 호출문과 반환문에는 붙인다. 소스에서 줄을 바꾸었다는 이유로 두 문장의 세미콜론을 생략할 수 없다. 다만 이를 “모든 C 문장은 반드시 세미콜론으로 끝난다”는 규칙으로 확대하지 않는다.

헤더의 선언과 정보는 컴파일러가 함수 이름과 사용 규칙을 알게 한다. 함수 구현을 연결하는 일은 Chapter 2에서 배운 링크와 관련된다. 따라서 `stdio.h`를 포함하는 것과 라이브러리 구현을 연결하는 것은 구별해야 하며, 헤더 안에 `printf` 구현 자체가 들어 있다고 설명하지 않는다.

## 문제 4. 함수 호출 읽기

### 정답

함수 이름은 `printf`이며, 인수는 다음 순서로 **3개**다.

| 순서 | 인수 | 역할 |
|---:|---|---|
| 1 | `"Room %c: %d seats\n"` | 형식 문자열 |
| 2 | `'D'` | 첫 번째 형식 지정자 `%c`에 대응하는 문자 |
| 3 | `8` | 두 번째 형식 지정자 `%d`에 대응하는 정수 |

출력은 다음과 같으며, 마지막에 줄바꿈이 있다.

```text
Room D: 8 seats
```

화면에 출력하는 내용과 함수의 반환값은 서로 다른 개념이다. 이 호출이 정상적으로 출력하면 `printf`는 줄바꿈을 포함하여 출력한 문자 수인 **16**을 반환한다.

### 상세해설

인수는 호출의 괄호 안에 전달하는 항목이다. 형식 문자열도 함수에 전달하는 항목이므로 인수 개수에 포함한다. `%c`와 `%d`는 그 문자열 안에 있는 형식 지정자이며, 각각을 별도의 인수로 세지 않는다.

형식 문자열의 보통 글자는 그대로 출력되고, `%c` 자리에 `D`, `%d` 자리에 `8`이 표시된다. 뒤에 전달한 값을 형식 지정자에 순서대로 대응시키는 것이 이 문제의 핵심이다.

반환값의 문자 수는 다음처럼 확인할 수 있다. 이것은 인수와 반환값의 차이를 보여 주는 보충 설명이다.

| 출력 부분 | 문자 수 |
|---|---:|
| `Room ` | 5 |
| `D` | 1 |
| `: ` | 2 |
| `8` | 1 |
| ` seats` | 6 |
| 줄바꿈 `\n` | 1 |
| 합계 | 16 |

제시된 호출문은 반환값을 사용하지 않으므로 화면에 숫자 16이 추가로 출력되지는 않는다. 화면에는 안내 내용이 전달되고, 반환값은 호출한 쪽으로 돌아온다. 출력 오류가 생기면 `printf`는 음수를 반환하지만, 여기서는 출력이 정상적으로 끝나는 경우를 가정한다.

## 문제 5. 변수와 출력 결과 추적하기

### 정답

| 실행한 줄 | `saved` | `current` | 화면 출력 |
|---|---:|---|---|
| `int saved = 12;` | 12 | 아직 선언 전 | 없음 |
| `int current = saved;` | 12 | 12 | 없음 |
| `saved = 19;` | 19 | 12 | 없음 |
| `current = current + 4;` | 19 | 16 | 없음 |
| `printf("%d %d\n", saved, current);` | 19 | 16 | `19 16`과 줄바꿈 |

마지막 출력 결과는 다음과 같다.

```text
19 16
```

### 상세해설

`int current = saved;`는 그 시점의 `saved` 값인 12를 읽어 `current`의 처음 값으로 저장한다. 두 변수는 각각 값을 보관하므로, 나중에 `saved`를 19로 바꾸어도 `current`는 12를 유지한다. 초기화로 값을 받는 것은 두 변수를 계속 연결하는 일이 아니다.

`current = current + 4;`에서는 먼저 오른쪽의 현재 값 12에 4를 더하여 16을 구한다. 그 값을 왼쪽의 `current`에 저장한다. 이 과정은 `saved`를 바꾸지 않는다. 마지막 `printf`에서는 첫 `%d`에 `saved`, 두 번째 `%d`에 `current`를 대응시켜 19와 16을 출력한다. 값을 출력하는 이 호출 역시 두 변수의 값을 바꾸지 않는다.

## 문제 6. 계산식 고르기

### 정답

| 구하려는 것 | C 수식 | 결과 |
|---|---|---:|
| 스티커 29장을 6장씩 넣을 때 꽉 채운 봉투 수 | `29 / 6` | 4개 |
| 위 경우의 남은 스티커 수 | `29 % 6` | 5장 |
| 처음 29장에 4장을 추가한 장수 | `29 + 4` | 33장 |
| 처음 29장에서 3장을 사용한 뒤의 장수 | `29 - 3` | 26장 |
| 꽉 채운 봉투 5개에 들어가는 장수 | `5 * 6` | 30장 |

`29 / 6`의 두 피연산자는 정수이므로 정수 몫 4를 구하며, 소수 부분은 보관하지 않는다.

### 상세해설

29장 안에는 6장 묶음이 온전히 네 번 들어간다. 네 봉투에 넣은 장수는 24장이며, 5장이 남는다. 따라서 `/`는 완성된 묶음 수를, `%`는 묶고 남은 수를 구하는 데 알맞다. `29 = 6 × 4 + 5`로 결과를 확인할 수 있다.

정수 나눗셈 결과 4는 소수 몫을 반올림한 값이 아니다. 이 문제처럼 0 이상의 정수를 양의 정수로 나누면 소수 부분을 버린 몫을 얻는다. 정수 나머지 `%`는 그 몫과 별개로 남는 수를 구한다.

뒤의 세 상황은 처음 문제에서 남은 5장을 기준으로 이어 계산하는 것이 아니라 각각 주어진 조건으로 계산한다. “처음 29장에 추가”는 `29 + 4`, “처음 29장에서 사용”은 `29 - 3`이다. 봉투 5개에 각각 6장씩 들어가면 `5 * 6`으로 계산한다. C의 곱셈 기호는 `*`다.

## 문제 7. 형식과 줄바꿈 맞추기

### 정답

`main` 안에 넣을 네 호출문은 다음과 같다.

```c
printf("%d\n", 7);
printf("%f\n", 2.5);
printf("%c\n", 'R');
printf("%s\n", "Focus");
```

출력 결과는 다음과 같다.

```text
7
2.500000
R
Focus
```

### 상세해설

| 지정자 | 이 호출에서 전달한 값 | 출력 의미 |
|---|---|---|
| `%d` | 정수 `7` | `int` 값을 10진수로 표시한다. |
| `%f` | 실수 `2.5` | `double` 값을 소수점 형태로 표시한다. |
| `%c` | 문자 `'R'` | 문자 하나를 표시한다. |
| `%s` | 문자열 `"Focus"` | 문자열의 글자를 표시한다. |

`2.5`는 이 호출에서 `double`형 값이다. 별도 정밀도를 지정하지 않은 `%f`는 소수점 이하 여섯 자리를 표시하므로 `2.500000`이 나온다. 형식 지정자를 바꾼다고 전달한 값이 그 형식에 맞는 종류로 자동 변환되는 것은 아니므로, 형식과 값의 종류를 맞추어야 한다.

`'R'`은 작은따옴표로 적은 문자이고, `"Focus"`는 큰따옴표로 적은 문자열이다. 각 형식 문자열 끝의 `\n`은 줄바꿈 문자를 나타내므로 네 결과가 각각 다른 줄에 표시된다. 소스 코드의 네 줄 배치만으로 화면이 네 줄이 되는 것은 아니다. `\n`에는 역슬래시를 사용하며 `/n`으로 적지 않는다.

## 문제 8. 입력값과 반환값 구별하기

### 정답

예제 E를 매번 새로 실행했을 때의 결과는 다음과 같다.

| 입력 | `scanf` 반환값 | `number`에 새 정수가 저장되는가? | 실패 처리 수행 | `Read: ...` 출력 |
|---|---:|---|---|---|
| `27` | 1 | 예, 27을 저장한다. | 아니요 | `Read: 27` |
| `0` | 1 | 예, 0을 저장한다. | 아니요 | `Read: 0` |
| `abc` | 0 | 아니요, 요청한 정수가 저장되지 않는다. | 예 | 출력하지 않는다. |

`number`가 0인지 검사하는 것으로 입력 실패를 알아낼 수 없다. **0도 정상적으로 입력할 수 있는 정수**이며, 입력한 값과 입력 성공을 알리는 반환값은 별개다.

### 상세해설

`scanf("%d", &number)`는 정수 하나의 변환과 저장을 요청한다. 이 작업에 성공하면 숫자가 27이든 0이든 반환값은 1이다. 실제로 읽은 정수는 `number`에 저장된다. `if`가 비교하는 대상은 그 정수가 아니라 `scanf`가 돌려준 성공 개수다.

`abc`를 입력하면 처음부터 정수로 맞춰 읽을 수 없으므로 이 경우의 반환값은 0이다. 예제 E에서는 `number`를 초기화하지 않고 선언했으며, 실패한 입력도 새 값을 저장하지 않는다. 따라서 실패 뒤의 `number`를 0이라고 가정하거나, 그 값을 읽어서 실패 여부를 판단해서는 안 된다.

예제 E의 `!= 1` 검사는 실패 시 안내 문구를 출력하고 `return 1;`로 `main`을 끝낸다. 그러므로 값을 얻지 못한 `number`를 출력하는 줄에 도달하지 않는다. 입력 전에 입력 자체가 끝난 경우도 성공값 1이 아니므로 같은 실패 처리로 종료한다.

입력 숫자 0과 반환값 0은 다음처럼 구별한다.

- 입력 숫자 0: 변환과 저장에 성공하여 `number`에는 0, 반환값에는 1이 있다.
- `abc`에 대한 반환값 0: 정수 저장에 성공하지 못했으며, 실패 처리가 필요하다.

## 문제 9. 입력 실패를 무시한 코드 고치기

### 정답

`main` 안에 들어갈 수정된 코드 조각은 다음과 같다.

```c
int count;

if (scanf("%d", &count) != 1)
{
    printf("Input failed.\n");
    return 1;
}

printf("Pages: %d\n", count * 4);
```

`count`를 0으로 초기화하는 것만으로는 문제가 해결되지 않는다. 입력 성공 여부를 확인하고, 실패하면 계산 전에 종료해야 한다.

### 상세해설

원래 코드에서는 `scanf`의 반환값을 확인하지 않은 채 곧바로 `count * 4`를 계산한다. `abc`를 입력하면 정수가 저장되지 않으므로, 아직 값을 받지 못한 `count`를 계산에 쓰게 된다. 이 문제의 잘못된 코드를 그대로 실행하여 결과를 추측하지 않는다.

수정 코드에서는 `scanf`가 1을 반환한 경우에만 출력문에 도달한다. 정수 입력에 실패하면 안내하고 `return 1;`로 끝내므로 `count`를 사용하지 않는다. 성공한 값은 문제의 가정대로 0부터 20까지라고 보고 별도의 범위 검사는 추가하지 않는다.

`int count = 0;`으로 바꾸었더라도 입력 실패를 확인하지 않으면, `abc`를 입력했을 때 처음 값 0이 남아 `Pages: 0`을 출력할 수 있다. 그러면 실패한 입력을 정상 입력 0과 구별하지 못한다. 초기값을 넣는 것과 입력 성공을 확인하는 것은 목적이 다르며, 반환값 검사는 여전히 필요하다.

이 코드는 완전한 프로그램이 아니라 `main`의 몸체에 넣는 조각이다. 실행할 때는 `stdio.h`, `int main(void)`와 몸체를 갖추고, 성공 경로의 마지막에 `return 0;`을 둔다.

## 문제 10. &의 역할 설명하기

### 정답

| 호출 | 전달하는 표현 | 필요한 정보 |
|---|---|---|
| `printf("%d\n", number);` | `number` | 출력할 **현재 값** |
| `scanf("%d", &number);` | `&number` | 읽은 정수를 저장할 **위치** |

여기서 `&`는 변수의 주소, 곧 저장 위치를 구하는 연산자다. 입력 전용 기호가 아니다. “입력이면 항상 붙이고 출력이면 절대 붙이지 않는다”는 규칙으로 일반화하면 안 된다.

### 상세해설

`number`라는 표현은 변수에 저장된 현재 값을 읽어 전달한다. `printf`의 `%d`는 그 값을 정수로 표시해야 하므로 현재 값이 필요하다. 반면 `scanf`의 `%d`는 새로 읽은 정수를 변수에 써 넣어야 하므로, 이 호출에는 저장할 위치인 `&number`를 전달한다.

차이는 함수가 입력용인지 출력용인지라는 이름만으로 결정되는 것이 아니라, 그 호출이 어떤 정보를 요구하는지에 있다. 따라서 친구의 말 중 제시된 두 호출에서 `&`의 유무를 구별한 부분은 맞지만, 이를 모든 입력과 출력에 적용한 결론은 잘못되었다.

이 장에서 익힌 입력 패턴은 **`%d`와 하나의 `int` 변수**에 대한 것이다. 앞으로 다른 입력 대상을 배우면 필요한 인수의 형태도 달라질 수 있다. 지금은 “이 변수에 저장하기 위해 그 위치를 알려 준다”는 설명에 머물며, 주소와 포인터의 전체 의미는 Chapter 12에서 배운다.

## 문제 11. 작은 프로그램 직접 작성하기

### 정답

다음은 `printing_ticket.c`로 저장할 수 있는 완전한 모범답안이다.

```c
#include <stdio.h>

int main(void)
{
    int count;
    printf("Sheets (0-20):\n");

    if (scanf("%d", &count) != 1)
    {
        printf("Input failed.\n");
        return 1;
    }

    int total = count * 150;
    printf("Total: %d won\n", total);
    return 0;
}
```

### 상세해설

이 프로그램은 입력·처리·출력 순서로 읽을 수 있다.

| 단계 | 해당 부분 | 역할 |
|---|---|---|
| 입력 | `scanf("%d", &count)`와 반환값 검사 | 장수를 저장하는 데 성공했는지 확인한다. |
| 처리 | `int total = count * 150;` | 장수에 한 장의 가격 150원을 곱한다. |
| 출력 | `printf("Total: %d won\n", total);` | 총액을 원 단위로 표시한다. |

`count`는 입력이 성공한 다음에만 계산에 사용한다. 실패하면 `Input failed.`를 표시하고 즉시 끝나므로 총액은 출력하지 않는다. 성공한 경우 마지막 `return 0;`으로 성공 종료 상태를 반환한다. 실패 시 사용하는 1은 이 책의 MSVC/GCC 실습 환경에서 따르는 종료 상태 관례다.

문제는 성공한 입력이 0부터 20까지라고 가정하며, 범위 검사를 요구하지 않는다. 모범답안은 이 가정을 따르는 작은 연습용 프로그램이다. 정수를 읽는 데 성공한 뒤 장수 범위나 입력 한 줄 전체를 검사하는 코드는 포함하지 않는다.

C17에서는 입력 검사 뒤에 `total`을 선언할 수 있다. 이름을 사용하기 전에 선언해야 한다는 규칙은 그대로이며, 이 배치는 성공한 장수를 얻은 뒤 총액을 계산한다는 순서를 드러낸다. 변수 이름이나 안내 문구가 달라도 입력 실패를 확인하고 같은 총액을 구하면 올바른 답이다.

#### 빌드와 실행 확인

GCC에서 사용할 명령은 다음과 같다.

```text
gcc -std=c17 -Wall -Wextra printing_ticket.c -o printing_ticket
```

모범답안을 GCC 13.3.0에서 위 C17·경고 옵션으로 실제 빌드했으며, 경고 0개·오류 0개였다. 입력별로 프로그램을 새로 실행한 결과는 다음과 같다. 표의 출력은 첫 안내 문구 `Sheets (0-20):` 다음에 나오는 내용이다.

| 입력 | 예상 출력 | GCC 실제 출력 | 실제 종료값 |
|---|---|---|---:|
| `0` | `Total: 0 won` | 예상과 일치 | 0 |
| `4` | `Total: 600 won` | 예상과 일치 | 0 |
| `20` | `Total: 3000 won` | 예상과 일치 | 0 |
| `abc` | `Input failed.`; 총액 출력 없음 | 예상과 일치 | 1 |

MSVC에서는 먼저 `cl /std:c17 /W4 printing_ticket.c`의 실제 진단을 확인한다. 표준 `scanf`에 C4996이 나오면 승인 본문의 방법대로 해당 실습 빌드에만 아래 설정을 적용한다.

```text
cl /std:c17 /W4 /D_CRT_SECURE_NO_WARNINGS printing_ticket.c
```

`/D_CRT_SECURE_NO_WARNINGS`는 MSVC용 빌드 설정이며 C 문법이 아니다. 소스에 정의를 추가하거나 `scanf_s`로 바꾸지 않고, `/W4`와 입력 반환값 검사를 유지한다. 이번 작성 환경에는 MSVC가 없어 위 두 MSVC 명령은 실행하지 않았다. 본문 예제의 이전 MSVC 통과 기록을 이 새 모범답안의 검증 결과로 대신하지 않는다.

## 문제 12. 두 기록을 합쳐 표시하기 〔심화·도전〕

### 정답

다음은 `two_study_records.c`로 저장할 수 있는 완전한 모범답안이다.

```c
#include <stdio.h>

int main(void)
{
    int morning;
    int afternoon;

    printf("Morning minutes:\n");
    if (scanf("%d", &morning) != 1)
    {
        printf("Input failed.\n");
        return 1;
    }

    printf("Afternoon minutes:\n");
    if (scanf("%d", &afternoon) != 1)
    {
        printf("Input failed.\n");
        return 1;
    }

    int total = morning + afternoon;
    int hours = total / 60;
    int minutes = total % 60;
    printf("Total: %d h %d min\n", hours, minutes);
    return 0;
}
```

### 상세해설

실행 순서는 다음과 같다.

1. 오전 안내 문구를 출력하고 `morning`에 정수를 읽는다.
2. 첫 `scanf`의 반환값을 확인한다. 1이 아니면 실패를 알리고 종료한다.
3. 첫 입력이 성공한 경우에만 오후 안내 문구를 출력하고 `afternoon`에 정수를 읽는다.
4. 둘째 `scanf`의 반환값을 확인한다. 1이 아니면 실패를 알리고 종료한다.
5. 두 입력이 모두 성공한 뒤 `morning + afternoon`을 `total`에 저장한다.
6. `total / 60`으로 온전한 시간 수를 구한다.
7. `total % 60`으로 남은 분을 구한다.
8. 시간과 분을 출력하고 성공 종료 상태 0을 반환한다.

오전 120분, 오후 90분을 입력했다면 계산값은 다음과 같다.

| 변수 | 계산 또는 입력 | 저장된 값 |
|---|---|---:|
| `morning` | 첫 입력 | 120 |
| `afternoon` | 둘째 입력 | 90 |
| `total` | `120 + 90` | 210 |
| `hours` | `210 / 60` | 3 |
| `minutes` | `210 % 60` | 30 |

따라서 `Total: 3 h 30 min`을 출력한다. 여기서 시간 수와 남은 분은 같은 합계에서 각각 몫과 나머지로 구한다. 오전과 오후를 먼저 합치므로 두 기록의 분을 따로 표시한 뒤 더할 필요는 없다.

첫 입력 성공이 둘째 입력의 성공까지 보장하지는 않는다. 첫 입력이 120이고 둘째 입력이 `abc`라면 두 번째 실패 처리에서 끝나므로 합계 계산에 도달하지 않는다. 첫 입력부터 `abc`라면 첫 번째 실패 처리에서 끝나며, 오후 안내 문구와 두 번째 `scanf`에도 도달하지 않는다. 두 검사가 각각 있어야 값을 얻지 못한 변수를 사용하지 않을 수 있다.

각 성공 입력은 문제의 가정대로 0부터 600까지로 보고 범위 검사는 생략한다. 첫 입력이나 둘째 입력이 0이어도 정수로 저장하는 데 성공하면 해당 `scanf`는 1을 반환하므로, 0을 입력 실패로 처리하지 않는다. 입력을 다시 받는 반복문과 별도 함수는 필요하지 않다.

#### 빌드와 실행 확인

GCC 명령은 다음과 같다.

```text
gcc -std=c17 -Wall -Wextra two_study_records.c -o two_study_records
```

MSVC에서는 아래 두 설정의 진단을 구별하여 기록한다. 두 번째 명령은 `scanf`의 C4996 진단을 위한 프로젝트의 실습용 설정이다.

```text
cl /std:c17 /W4 two_study_records.c
cl /std:c17 /W4 /D_CRT_SECURE_NO_WARNINGS two_study_records.c
```

모범답안을 GCC 13.3.0에서 같은 C17·경고 옵션으로 실제 빌드했으며, 경고 0개·오류 0개였다. 아래 각 입력을 새 실행에 주어 확인했고, 모든 예상 출력과 종료값이 일치했다. 이 프로그램도 이번 환경에서는 MSVC로 실행하지 않았다.

| 오전 입력 | 오후 입력 | 예상 결과 | 예상 종료값 |
|---|---|---|---:|
| `120` | `90` | `Total: 3 h 30 min` | 0 |
| `0` | `0` | `Total: 0 h 0 min` | 0 |
| `600` | `600` | `Total: 20 h 0 min` | 0 |
| `120` | `abc` | 오후 안내 뒤 `Input failed.`; 합계 출력 없음 | 1 |
| `abc` | 입력받지 않음 | 오전 안내 뒤 `Input failed.`; 오후 안내와 합계 출력 없음 | 1 |

검증할 때는 합계의 숫자만 보지 말고 실패 경로의 출력과 종료값도 확인한다. 특히 첫 입력에서 실패했는데 오후 입력을 계속 받는다면 문제의 요구와 다르다. 모든 성공 경로와 두 실패 경로가 명세대로 동작하는지가 이 도전 문제의 핵심이다.
